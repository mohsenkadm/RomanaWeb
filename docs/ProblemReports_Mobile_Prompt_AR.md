# برومبت تعديل تطبيق المندوب — إبلاغات المشاكل (Problem Reports)

انسخ هذا البرومبت كاملاً إلى ذكاء اصطناعي يعمل على تطبيق Flutter/الموبايل الخاص بالمندوب (SaleMan / Driver app).

---

## المهمة

أضف ميزة **إبلاغ مشكلة مرتبطة بطلب** في تطبيق المندوب، متوافقة مع الـ API الموجود في لوحة التحكم (RomanaWeb).

الهدف: المندوب يكتب نص بلاغ عن طلب مسند إليه، ويُرسل للسيرفر، ويظهر فوراً في لوحة التحكم `/Home/ProblemReports`.

---

## قواعد عامة

1. استخدم نفس `BASE_URL` و JWT الموجودين في التطبيق (بعد `SaleMan/Login`).
2. Role في التوكن يجب أن يكون `sal`.
3. أرسل الهيدر: `Authorization: Bearer {token}`.
4. `Content-Type: application/json` لطلبات POST.
5. تعامل مع شكل الاستجابة الموحد:
```json
{ "success": true|false, "msg": "...", "data": { } | [ ] }
```
6. لا تسمح بالإبلاغ إلا على طلبات **مسندة للمندوب الحالي**.
7. الواجهة عربية RTL، واضحة، بدون تعقيد زائد.

---

## حالات البلاغ (Status)

| القيمة | المعنى |
|--------|--------|
| `0` | قيد الانتظار |
| `1` | قيد المعالجة |
| `2` | حُلت |
| `3` | لم يتم حلها |

عند الإرسال من التطبيق الحالة دائماً تبدأ `0`.

---

## الـ APIs

### 1) إرسال بلاغ (مطلوب)

```
POST {BASE_URL}problem-reports
Authorization: Bearer {token}
Content-Type: application/json

{
  "orderId": 456,
  "message": "المطعم متأخر ولم يجهّز الطلب"
}
```

**نجاح نموذجي:**
```json
{
  "success": true,
  "msg": "تم إرسال البلاغ بنجاح",
  "data": {
    "problemReportId": 12,
    "orderId": 456,
    "orderNo": 1001,
    "status": 0,
    "statusLabel": "قيد الانتظار",
    "createdAt": "2026-08-21T..."
  }
}
```

**أخطاء متوقعة:**
- غير مصرح / حساب غير نشط
- نص البلاغ فارغ أو أطول من 2000 حرف
- الطلب غير موجود
- الطلب غير مسند لهذا المندوب

### 2) قائمة بلاغاتي (موصى به)

```
GET {BASE_URL}problem-reports/mine?take=50
Authorization: Bearer {token}
```

يعيد قائمة بلاغات المندوب الحالي (الأحدث أولاً) مع: `problemReportId`, `orderId`, `orderNo`, `message`, `status`, `statusLabel`, `createdAt`, `adminNote`.

---

## متطلبات الواجهة في تطبيق المندوب

1. **من شاشة تفاصيل الطلب / طلباتي:**
   - زر واضح: `إبلاغ عن مشكلة`
   - يظهر فقط إذا الطلب مسند للمندوب الحالي.

2. **شاشة/Bottom sheet كتابة البلاغ:**
   - عرض رقم الطلب (`orderNo`) بشكل ثابت (غير قابل للتعديل).
   - حقل نص متعدد الأسطر للبلاغ (إجباري).
   - حد أقصى 2000 حرف مع عدّاد إن أمكن.
   - زر إرسال + حالة تحميل أثناء الطلب.
   - عند النجاح: Toast/SnackBar ثم إغلاق الشاشة وتحديث القائمة.

3. **شاشة بلاغاتي (اختياري لكن مفضّل):**
   - قائمة من `GET problem-reports/mine`
   - بطاقة لكل بلاغ: رقم الطلب، التاريخ، نص مختصر، badge الحالة.
   - الألوان المقترحة:
     - 0 برتقالي، 1 أزرق، 2 أخضر، 3 أحمر.

4. **معالجة الأخطاء:**
   - اعرض `msg` القادم من السيرفر للمستخدم.
   - لا ترسل الطلب إذا النص فارغ.

## نموذج بيانات مقترح (Dart)

```dart
class ProblemReport {
  final int problemReportId;
  final int orderId;
  final int? orderNo;
  final String message;
  final int status;
  final String statusLabel;
  final DateTime createdAt;
  final String? adminNote;
}
```

---

## اختبار يدوي مطلوب

- [ ] تسجيل دخول مندوب نشط.
- [ ] فتح طلب مسند إليه → إرسال بلاغ → يظهر في لوحة التحكم.
- [ ] محاولة إبلاغ على طلب غير مسند إليه → رسالة رفض.
- [ ] نص فارغ → منع محلي أو رسالة سيرفر.
- [ ] `GET problem-reports/mine` يعرض البلاغ الجديد أولاً.
- [ ] مندوب غير نشط (`IsActive=false`) لا يستطيع الإرسال.

---

## ملاحظات تقنية

- المسار: `problem-reports` (kebab-case) وليس `ProblemReports`.
- الحقل في الـ body هو `orderId` (OrderId الداخلي) وليس رقم الطلب الظاهر فقط — إن كان عندك فقط `orderNo` فاحصل على `orderId` من تفاصيل الطلب أولاً.
- لوحة التحكم تدير الحالات؛ التطبيق حالياً يُرسل فقط ويعرض الحالة إن وُجدت في `mine`.
- لا حاجة لـ SignalR لهذه الميزة في الإصدار الأول.
