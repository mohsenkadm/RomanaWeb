# برومبت تعديل تطبيق الزبون — OTP 6 أرقام + حماية الأمان

انسخ هذا البرومبت كاملاً إلى ذكاء اصطناعي يعمل على تطبيق Flutter/الموبايل الخاص بالزبون (Customer / User app).

---

## المهمة

حدّث تطبيق الزبون ليتوافق مع تغييرات الأمان الجديدة في الـ API (RomanaWeb):

1. كود OTP أصبح **6 أرقام** بدل 4.
2. الكود له **صلاحية زمنية** و**rate limit** عند الإرسال والتحقق.
3. بعض الـ endpoints لم تعد عامة وتحتاج JWT أو صارت مخصصة للوحة التحكم فقط.

الهدف: تسجيل الدخول / نسيان كلمة السر / تأكيد الحساب يعملون بدون أخطاء بعد تحديث السيرفر.

---

## قواعد عامة

1. استخدم نفس `BASE_URL` و JWT الموجودين في التطبيق.
2. تعامل مع شكل الاستجابة الموحد:
```json
{ "success": true|false, "msg": "...", "data": { } | [ ] | null }
```
3. اعرض دائماً `msg` القادم من السيرفر للمستخدم (Toast/SnackBar) — الرسائل أصبحت أدق (انتهاء صلاحية، انتظر ثوانٍ، تجاوز الحد...).
4. الواجهة عربية RTL، واضحة، بدون تعقيد زائد.
5. لا تستدعِ من التطبيق مسارات جلب كل الزبائن (`Users/GetAll` وغيرها) — هذه للوحة التحكم فقط.

---

## سياسة OTP الجديدة (مهم جداً)

| البند | القيمة |
|--------|--------|
| طول الكود | **6 أرقام** (مثال: `482915`) |
| صلاحية الكود الواحد | **5 دقائق** |
| حد الإرسال | **3 رسائل كل 15 دقيقة** لكل رقم هاتف |
| فاصل بين إرسالين | **60 ثانية على الأقل** |
| محاولات التحقق الفاشلة | بعد **5** محاولات يُبطَل الكود ويجب طلب كود جديد |
| بعد النجاح | الكود يُمسح ولا يُعاد استخدامه |

## الـ Endpoints المتأثرة (حدّثها كلها)

### 1) إرسال OTP لتسجيل الدخول

```
POST {BASE_URL}Users/Login/SendOtp/{Phone}
```

- `Phone`: 11 رقم (مثال: `07701234567`).
- بدون توكن.
- نجاح نموذجي: `تم ارسال كود التحقق عبر الواتساب`
- أخطاء متوقعة من السيرفر:
  - `انتظر X ثانية قبل اعادة ارسال الكود`
  - `تم تجاوز الحد المسموح (3 رسائل خلال 15 دقيقة)...`
  - حساب محظور / غير فعال / رقم غير 11 خانة

**UI مطلوب:**
- زر «إعادة إرسال» معطّل مع عدّاد تنازلي **60 ثانية** على الأقل بعد كل إرسال ناجح.
- حقل إدخال الكود: **6 خانات** (numeric فقط).

---

### 2) التحقق من OTP وتسجيل الدخول

```
POST {BASE_URL}Users/Login/VerifyOtp/{Phone},{Code}
```

- مثال: `.../Users/Login/VerifyOtp/07701234567,482915`
- `Code` يجب أن يكون **6 أرقام** (ليس 4).
- بدون توكن.
- عند النجاح: احفظ `token` وبيانات المستخدم كما كان سابقاً.
- أخطاء متوقعة:
  - `كود التحقق غير صحيح`
  - `انتهت صلاحية كود التحقق، اطلب كوداً جديداً`
  - `تم تجاوز محاولات التحقق، اطلب كوداً جديداً`
  - `لا يوجد كود تحقق فعال، اطلب كوداً جديداً`

**UI مطلوب:**
- لا ترسل التحقق إذا طول الكود ≠ 6.
- عند رسالة انتهاء الصلاحية أو تجاوز المحاولات: وجّه المستخدم لإعادة الإرسال.

---

### 3) نسيان كلمة السر — طلب الكود

```
POST {BASE_URL}Users/ForgatePassword/{Phone}
```

- نفس سياسة الـ rate limit والـ OTP 6 أرقام.
- قد يرفض حساب محظور / غير فعال.

---

### 4) تعيين كلمة مرور جديدة بالكود

```
POST {BASE_URL}Users/Update_Pass_WithCode/{Pass},{Phone},{Code}
```

- `Code`: **6 أرقام**.
- `Pass`: **6 أحرف على الأقل** (تحقق محلي + رسالة السيرفر).
- نفس قواعد انتهاء الصلاحية ومحاولات الفشل.

**UI مطلوب:**
- شاشة: رقم الهاتف + كود 6 خانات + كلمة مرور جديدة (+ تأكيد إن وُجد).
- منع الإرسال إذا الكود ليس 6 أو كلمة المرور أقصر من 6.

---

### 5) تأكيد الكود (إن كان مستخدماً في التطبيق)

```
POST {BASE_URL}Users/ConfirmCode/{code},{Phone}
```

- `code`: **6 أرقام**.
- **تغيير مهم في الاستجابة:** لم يعد السيرفر يرجع كائن المستخدم كاملاً مع password.
- نجاح نموذجي `data` تقريباً:
```json
{
  "userId": 15,
  "name": "...",
  "phone": "0770...",
  "isConfirm": true
}
```
- حدّث الـ model/parsing ليتوافق مع الشكل المختصر (لا تعتمد على `password` أو حقول حساسة).

---

### 6) إرسال OTP عام (إن كان مستخدماً)

```
POST {BASE_URL}Users/SendOTPCodeToPhoneNo/{Phone}
```

- الكود المُرسَل أصبح 6 أرقام ويخضع لنفس الـ rate limit.
- حدّث أي شاشة تعتمد عليه لنفس UX (6 خانات + عدّاد إعادة إرسال).

---

### 7) تجديد التوكن — تغيّر أمني مهم

```
POST {BASE_URL}Users/RefreshToken/{Id}
Authorization: Bearer {token}
```

- **لم يعد Anonymous.**
- أرسل الهيدر: `Authorization: Bearer {token}` الحالي.
- يُسمح فقط بتجديد توكن **نفس المستخدم** (`Id` = userId المسجّل دخول).
- إن فشل بـ 401 / «غير مصرح»: امسح الجلسة ووجّه لشاشة تسجيل الدخول (OTP).

**افحص في الكود:**
- أي استدعاء قديم لـ `RefreshToken` بدون Bearer → أصلحه فوراً.
- لا تحاول تجديد توكن لمستخدم آخر.

## Endpoints ممنوع استدعاؤها من تطبيق الزبون

هذه أصبحت **لوحة التحكم / Admin فقط**. إن وُجدت في التطبيق احذفها أو عطّلها:

| Endpoint | السبب |
|----------|--------|
| `GET Users/GetAll` | قائمة كل الزبائن — Admin فقط |
| `GET Users/GetExcelAll` | تصدير — Admin فقط |
| `GET Users/GetById` | إلا إذا كان لنفس المستخدم بتوكنه (يفضّل عدم الاعتماد عليه للزبون) |
| `POST Users/PostAdmin` | Admin فقط |
| `DELETE Users/Delete` | Admin فقط |

تسجيل زبون جديد عبر `POST Users/Post` مع `UserId = 0` ما زال مسموحاً بدون توكن (إن كان مسار التسجيل التقليدي مستخدماً). تعديل حساب موجود يحتاج توكن نفس المستخدم.

## متطلبات الواجهة (Flutter)

1. **كل شاشات OTP:**
   - `TextField` / `PinCode` بطول **6**.
   - `keyboardType: TextInputType.number`
   - `maxLength: 6`
   - validation قبل الاستدعاء.

2. **إعادة الإرسال:**
   - Timer محلي 60 ثانية بعد إرسال ناجح.
   - عند رسالة السيرفر «انتظر X ثانية» استخدم نفس العدّاد أو اعرض الرسالة.

3. **انتهاء الصلاحية:**
   - رسالة واضحة + زر «إعادة إرسال الكود».
   - لا تُبقِ المستخدم عالقاً على كود منتهٍ.

4. **الأخطاء:**
   - اعرض `msg` كما هي من السيرفر.
   - لا تفترض أن الكود دائماً 4 أرقام في أي مكان (models، regex، UI، comments، tests).

5. **RefreshToken:**
   - أضف/تأكد من Interceptor يرسل Bearer.
   - عند فشل التجديد: logout نظيف.

## بحث واستبدال مطلوب داخل المشروع

ابحث في المشروع عن أي من التالي وحدّثه:

- `maxLength: 4` أو `length: 4` المرتبطة بـ OTP
- `RegExp` بطول 4 للكود
- نصوص/تلميحات: «أدخل الرمز المكون من 4 أرقام» → **6**
- أمثلة ثابتة مثل `1234` أو `4829` → أمثلة بـ 6 أرقام
- استدعاءات `RefreshToken` بدون header Authorization
- parsing لـ `ConfirmCode` يعتمد على `password` أو كائن `Users` كامل

## اختبار يدوي مطلوب

- [ ] إرسال OTP لرقم صحيح → يصل واتساب بكود **6** أرقام.
- [ ] إدخال 4 أرقام فقط → منع محلي أو رفض سيرفر.
- [ ] إدخال كود صحيح خلال 5 دقائق → دخول ناجح وحفظ التوكن.
- [ ] انتظار أكثر من 5 دقائق ثم التحقق → رسالة انتهاء صلاحية.
- [ ] الضغط على إعادة إرسال فوراً → رسالة انتظار / عدّاد 60 ثانية.
- [ ] أكثر من 3 إرسالات خلال 15 دقيقة → رسالة تجاوز الحد.
- [ ] 5 محاولات كود خاطئ → يطلب كوداً جديداً.
- [ ] نسيان كلمة السر بالكود 6 + كلمة مرور ≥ 6 → نجاح.
- [ ] `RefreshToken` مع Bearer لنفس userId → نجاح؛ بدون توكن → فشل وlogout.
- [ ] لا يوجد استدعاء لـ `Users/GetAll` من التطبيق.

## ملاحظات تقنية

- المسارات لم تتغير أسماءً؛ التغيّر في **الطول / الصلاحية / التوكن المطلوب / شكل بعض الاستجابات**.
- لا تعتمد على تخزين الكود محلياً لإعادة استخدامه لاحقاً — السيرفر يمسحه بعد النجاح أو الفشل المتكرر.
- إن كان عندك feature flags أو remote config لطول OTP، اجعله `6`.
- نفّذ بأقل تغيير ممكن على البنية الحالية (نفس Dio/http + نفس شاشات auth).
