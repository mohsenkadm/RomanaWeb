# برومبت Flutter — تعديل الملف الشخصي مع OTP عند تغيير الهاتف

انسخ هذا البرومبت كاملاً إلى ذكاء اصطناعي يعمل على تطبيق Flutter/الموبايل الخاص بالزبون (Customer / User app).

---

## المهمة

أضف/حدّث شاشة **تعديل الملف الشخصي** لتتوافق مع الـ API الجديد في RomanaWeb:

1. المستخدم يعدّل **الاسم، الهاتف، العنوان، نقطة الوظيفة** فقط — **بدون كلمة مرور**.
2. إن لم يتغيّر رقم الهاتف → حفظ مباشر.
3. إن تغيّر الرقم → السيرفر يرسل OTP عبر واتساب للرقم **الجديد**، ثم شاشة إدخال كود 6 أرقام لتأكيد التغيير.
4. لا تستخدم `Users/Post` لتغيير الهاتف بعد هذا التحديث.

---

## قواعد عامة

1. استخدم نفس `BASE_URL` و JWT الموجودين في التطبيق.
2. كل الطلبات الثلاثة تحتاج:
```
Authorization: Bearer {token}
```
3. شكل الاستجابة الموحد:
```json
{ "success": true|false, "msg": "...", "data": { } | null }
```
4. اعرض دائماً `msg` من السيرفر (Toast/SnackBar).
5. الواجهة عربية RTL.
6. **لا ترسل** `Lat` / `Long` / `CityId` / `Password` من هذه الشاشة — لها مسارات أخرى.

---

## الحقول المسموحة في الفورم

| الحقل | اسم Form | مطلوب | ملاحظات |
|--------|----------|--------|---------|
| الاسم | `Name` | نعم | نص |
| الهاتف | `Phone` | نعم | 11 رقم محلي عراقي، مثال `07701234567` |
| العنوان | `Address` | لا | نص |
| نقطة الوظيفة | `FunctionPoint` | لا | نص |

تحقق محلي قبل الإرسال:
- `Phone.length == 11` وأرقام فقط.
- `Name` غير فارغ.

---

## سياسة OTP (نفس سياسة التطبيق)

| البند | القيمة |
|--------|--------|
| طول الكود | **6 أرقام** |
| صلاحية الكود | **5 دقائق** |
| حد الإرسال | **3 رسائل كل 15 دقيقة** |
| فاصل بين إرسالين | **60 ثانية** |
| محاولات فاشلة | بعد **5** يُبطَل الكود |

القناة: واتساب (VerifyWay) — أخبر المستخدم أن الكود يصل على واتساب الرقم الجديد.

## الـ Endpoints

### 1) تحديث الملف الشخصي

```
POST {BASE_URL}Users/UpdateProfile
Content-Type: multipart/form-data
Authorization: Bearer {token}
```

**Body (form):**
- `Name`
- `Phone`
- `Address`
- `FunctionPoint`

لا ترسل `UserId` — السيرفر يأخذ الهوية من JWT.

#### أ) الرقم لم يتغيّر — نجاح مباشر

```json
{
  "success": true,
  "msg": "تم الحفظ بنجاح",
  "data": {
    "userId": 15,
    "name": "...",
    "phone": "0770...",
    "address": "...",
    "functionPoint": "...",
    "token": "...",
    "pendingPhone": null
  }
}
```

- حدّث بيانات المستخدم المحلية + احفظ `token` الجديد إن وُجد.
- أغلق الشاشة أو أظهر نجاحاً.

#### ب) الرقم تغيّر — يحتاج تحقق

```json
{
  "success": true,
  "msg": "تم تحديث بياناتك. تم ارسال كود التحقق للرقم الجديد عبر الواتساب",
  "data": {
    "requiresPhoneVerification": true,
    "pendingPhone": "07709998877",
    "user": {
      "userId": 15,
      "name": "...",
      "phone": "07701234567",
      "token": "..."
    }
  }
}
```

**مهم:**
- `user.phone` ما زال الرقم **القديم** حتى التأكيد.
- احفظ `pendingPhone` وانتقل فوراً لشاشة إدخال OTP.
- حدّث الاسم/العنوان محلياً من `user` إن رغبت (تم حفظها على السيرفر).

أخطاء متوقعة:
- `يجب كتابة رقم الهاتف 11 رقما`
- `الاسم مطلوب`
- `رقم الهاتف موجود سابقا`
- `انتظر X ثانية قبل اعادة ارسال الكود`
- `تم تجاوز الحد المسموح (3 رسائل خلال 15 دقيقة)...`
- حساب محظور / غير فعال / غير مصرح

---

### 2) تأكيد تغيير الهاتف بالكود

```
POST {BASE_URL}Users/ConfirmPhoneChange/{Code}
Authorization: Bearer {token}
```

مثال: `POST .../Users/ConfirmPhoneChange/482915`

- `Code`: **6 أرقام** فقط.
- لا ترسل إن الطول ≠ 6.

نجاح نموذجي:
```json
{
  "success": true,
  "msg": "تم تأكيد رقم الهاتف الجديد بنجاح",
  "data": {
    "userId": 15,
    "phone": "07709998877",
    "token": "..."
  }
}
```

- حدّث `phone` المحلي إلى الرقم الجديد.
- احفظ `token` الجديد.
- أغلق شاشة OTP وارجع للملف الشخصي.

أخطاء متوقعة:
- `كود التحقق غير صحيح`
- `انتهت صلاحية كود التحقق، اطلب كوداً جديداً`
- `تم تجاوز محاولات التحقق، اطلب كوداً جديداً`
- `لا يوجد كود تحقق فعال، اطلب كوداً جديداً`
- `لا يوجد طلب تغيير رقم هاتف قيد التحقق`
- `رقم الهاتف موجود سابقا`

---

### 3) إعادة إرسال OTP لتغيير الهاتف

```
POST {BASE_URL}Users/ResendPhoneChangeOtp
Authorization: Bearer {token}
```

- بدون body.
- يعمل فقط إن كان هناك `PendingPhone` على السيرفر.
- نجاح: رسالة إرسال واتساب.
- نفس رسائل الـ rate limit (60 ثانية / 3 لكل 15 دقيقة).

**UI:** زر «إعادة إرسال» معطّل مع عدّاد تنازلي **60 ثانية** بعد كل إرسال ناجح (من UpdateProfile أو Resend).

---

## تدفق الواجهة المطلوب

```
[شاشة تعديل الملف الشخصي]
  الحقول: Name, Phone, Address, FunctionPoint
  زر حفظ
        │
        ▼
  POST UpdateProfile
        │
   ┌────┴────┐
   │         │
 بدون OTP   requiresPhoneVerification == true
   │         │
 نجاح       [شاشة OTP]
 وإغلاق       - عرض pendingPhone
              - Pin 6 أرقام
              - تأكيد → ConfirmPhoneChange
              - إعادة إرسال → ResendPhoneChangeOtp
```

1. عبّئ الحقول من بيانات المستخدم الحالية عند فتح الشاشة.
2. لا تضع حقل كلمة مرور.
3. عند `requiresPhoneVerification`: لا تعتبر تغيير الهاتف مكتملاً حتى نجاح Confirm.
4. إن أغلق المستخدم شاشة OTP قبل التأكيد: الرقم القديم يبقى القديم؛ يمكنه لاحقاً إعادة المحاولة بتغيير الرقم مرة أخرى أو استدعاء Resend إن بقي الطلب معلّقاً.

## ممنوع / تجنّب

| لا تفعل | السبب |
|---------|--------|
| `POST Users/Post` لتغيير الهاتف | لم يعد يغيّر `Phone` للزبون — مسار OTP فقط |
| إرسال بدون Bearer | 401 / غير مصرح |
| OTP بطول 4 | السيرفر يتوقع 6 |
| تعديل Lat/Long/CityId من هذه الشاشة | مسارات أخرى |

---

## اختبار يدوي مطلوب

- [ ] تعديل الاسم/العنوان/نقطة الوظيفة فقط (نفس الهاتف) → نجاح فوري بدون OTP.
- [ ] تغيير الهاتف لرقم جديد صحيح → OTP على واتساب الرقم الجديد.
- [ ] إدخال كود صحيح خلال 5 دقائق → `phone` يتحدث محلياً وفي السيرفر.
- [ ] كود خاطئ → رسالة السيرفر؛ بعد 5 فشل يطلب كوداً جديداً.
- [ ] إعادة إرسال فوراً → انتظار / عدّاد 60 ثانية.
- [ ] رقم مستخدم مسبقاً → `رقم الهاتف موجود سابقا`.
- [ ] رقم ليس 11 خانة → منع محلي + رسالة سيرفر.
- [ ] بدون توكن → فشل وlogout إن لزم.
- [ ] لا يوجد استدعاء `Users/Post` لتعديل الهاتف من شاشة البروفايل.

## ملاحظات تقنية

- نفّذ بأقل تغيير على البنية الحالية (نفس Dio/http + نفس تخزين التوكن).
- إن كان `data` أحياناً كائن مستخدم مباشرة وأحياناً `{ requiresPhoneVerification, pendingPhone, user }` — افحص وجود `requiresPhoneVerification` أولاً قبل parsing كـ User.
- بعد أي نجاح يعيد `token`، حدّث الـ token المخزّن.
- نفّذ الشاشة بالكامل مع RTL ونصوص عربية واضحة.
